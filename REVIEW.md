# MyPlants — разбор кода

1 августа 2026. Проект прочитан целиком: 3 275 строк, 20 файлов.

---

## Корень проблемы был не в свайпе

Свайп ощущался сломанным, но причина лежала на два слоя ниже. Фотографии читались из IndexedDB и конвертировались в **base64 через `FileReader.readAsDataURL`** — на каждый показ, для каждой карточки.

Что из этого следовало:

**Раз.** Base64 на треть больше двоичных данных и целиком лежит в памяти строкой. Снимок с телефона на 5 МБ превращался в строку почти на 7 МБ.

**Два.** Сжатия при загрузке не было вообще. `handleFileChange` брал исходный `File` и складывал как есть. Двадцать растений по три фотографии — это больше сотни мегабайт в хранилище.

**Три.** И самое разрушительное: `app/page.tsx` перезагружал весь список **и на `visibilitychange`, и на `focus`** — оба события срабатывают. Каждая перезагрузка возвращала новый массив из IndexedDB, `plant.photos` получал новую ссылку, `useEffect([photos])` в галерее считал зависимость изменившейся и **перечитывал и заново декодировал все фотографии всех карточек.** При каждом возврате на вкладку.

**Четыре.** `FullscreenPhotoViewer` при открытии грузил те же самые фотографии второй раз, независимо от галереи. Две копии каждой base64-строки в памяти одновременно.

Отсюда и рывки: пока палец ведёт по экрану, главный поток занят декодированием мегабайтов base64. На iOS вкладку при этом могло просто выгрузить из памяти.

## Что исправлено

### `lib/repositories/photosRepository.ts` — переписан

`URL.createObjectURL(blob)` вместо base64. Object URL — это указатель на блоб, а не его копия, создаётся мгновенно и не занимает память сверх самого блоба.

Добавлено:

- `revokeUrls(urls)` — освобождение. Обязательно к вызову при размонтировании, иначе блобы висят до перезагрузки вкладки.
- `Promise.allSettled` вместо `Promise.all`. Раньше **один битый ключ обрушивал загрузку всех фотографий карточки** — вместо девяти живых фото показывалось «No photo». Теперь на месте пропавшего фото пустая строка, остальные показываются.
- `getBlobById` — сырой блоб. Понадобится для выгрузки и отправки на сервер, где object URL бесполезен.

### `components/PhotoGallery.tsx` — переписан в тикете D2

Этот раздел долгое время утверждал, что файл переписан, хотя правки сюда не дошли: обнаружилось при разборе главного экрана (D1), исправлено тикетом D2. Таблица ниже — история, но короткая: с момента заявления до фактической правки прошло больше половины бэклога, и всё это время `CLAUDE.md` ссылался на этот файл как на образец.

Найденные баги:

| Было | Почему ломалось |
|---|---|
| `if (!touchStart) return` | `touchStart` — это координата X. Касание у самого левого края даёт `0`, `!0` истинно, обработчик выходил. Нужно `=== null` |
| Отслеживался только X | При вертикальном скролле ленты набегал горизонтальный дрейф, и на отпускании ветка «сдвиг меньше 50px» **открывала фото на весь экран во время прокрутки**. Скорее всего это и был главный раздражитель |
| Тап определялся как `touchEnd === null` | `onTouchMove` срабатывает от малейшего дрожания, поэтому `touchEnd` почти никогда не был `null`. Работал только запасной путь через «сдвиг меньше порога» — то есть **любой короткий свайп открывал фото вместо листания** |
| Трансформ обновлялся только на `touchEnd` | Фото не следовало за пальцем. Тянешь — ничего не двигается до отпускания |
| `window.addEventListener('keydown')` в каждой галерее | Двадцать растений — двадцать слушателей. Стрелки листали **все карточки одновременно** |
| `width: N*100%` у ленты, `100/N%` у слайдов | Работало, но хрупко. Стандартный приём: слайды `flex: 0 0 100%`, сдвиг `-i*100%` |
| `borderRadius: '12px 0 0'` | Три значения означают: левый верхний 12, правый верхний 0, правый нижний 0, левый нижний 0. Округлялся только один угол — почти наверняка не то, что задумывалось |

Как сделано теперь: ось жеста определяется один раз за касание, вертикаль полностью отдаётся браузеру через `touch-action: pan-y`, лента живо следует за пальцем, на краях сопротивление в три раза, тап определяется по фактическому сдвигу и времени, короткий быстрый флик тоже листает, object URL освобождаются в `cleanup`, зависимость эффекта — по содержимому массива ключей.

К списку выше разбор D1 добавил ещё два пункта, тоже закрытых: object URL не освобождались вовсе и `touch-action` был `pan-x pan-y` вместо `pan-y`. Пороги жеста теперь общие с просмотрщиком, а режим жеста хранится в ref: между `touchstart` и `touchend` React может не успеть перерисоваться.

### `components/FullscreenPhotoViewer.tsx` — переписан

Здесь правки дошли: `photos.join('|')` вместо ссылки на массив, `revokeUrls` в `cleanup`, `TAP_SLOP`, режимы жеста. Это и есть образец, на который стоит смотреть.

Дополнительно к тем же багам:

- **Панорамирование не имело границ** — увеличенное фото можно было утащить за пределы экрана в пустоту. Добавлен `clampPan` по фактическим размерам картинки.
- **Щипок оставлял состояние висящим.** Если убрать один палец из двух, `lastPinchDistance` сбрасывался только на `touchEnd`, и жест доламывался. Теперь переход «два пальца → один» обрабатывается явно.
- Фотографии больше не грузятся заново, а листаются той же лентой.
- Добавлено закрытие свайпом вниз с затемнением фона по мере оттягивания.
- `onClose` теперь принимает индекс, чтобы карточка синхронизировалась с тем фото, на котором закрыли.
- `document.body.style.overflow` восстанавливается к прежнему значению, а не к пустой строке.

### `lib/imageCompression.ts` — новый файл

Canvas-ресайз до 1600 пикселей по большей стороне, WebP при поддержке браузером иначе JPEG, качество 0.82. Типичная фотография становится 150–400 КБ вместо 3–8 МБ.

Аккуратности, которые там учтены: HEIC и GIF не трогаются (первый canvas не декодирует, у второго потеряется анимация); файлы меньше 300 КБ нормального размера оставляются как есть; при любой ошибке возвращается оригинал — потерять фотографию хуже, чем сохранить тяжёлой; если сжатие не уменьшило размер, берётся оригинал; обработка **последовательная**, потому что параллельное декодирование десятка снимков по 8 МБ надёжно роняет вкладку на телефоне.

### `components/AddPlantForm.tsx` — правки

Сжатие подключено перед записью, кнопка показывает прогресс «Обработка фото 2/5» и блокируется во время сохранения. Раньше при отправке ничего не происходило видимого несколько секунд, и можно было нажать повторно.

## Что осталось и стоит сделать дальше

### Сразу, дешёвое

**Убрать двойную перезагрузку в `app/page.tsx`.** Сейчас подписка и на `visibilitychange`, и на `focus` — оба вызывают `loadPlantsData`. Хватит одного `visibilitychange`. Это исправлено по симптому (эффект галереи больше не срабатывает вхолостую), но сама двойная загрузка списка осталась.

**Удалить мёртвые слои хранения.** В проекте живут три параллельных механизма: `lib/db` + `lib/repositories` (база `plant-collection-db`), `lib/photoStorage.ts` (отдельная база `plant-photos-db`) и `lib/plantStorage.ts` (localStorage). Последние два не импортируются ниоткуда, кроме миграции. Две открытые базы IndexedDB вместо одной и много кода, который будет путать.

**Инлайновые стили.** Работают, но каждый ре-рендер создаёт новые объекты стилей, и переиспользовать нечего. Дизайн-токены — цвета `#d9d0de`, `#8d80ad`, `#1b2021`, радиусы 16px, — стоит вынести в CSS-переменные. Особенно если UI будет меняться.

### Перед шерингом, обязательное

**`id: Date.now().toString()` не годится.** Два растения, добавленные в одну миллисекунду, получат одинаковый id. И при синхронизации с сервером такие идентификаторы столкнутся между устройствами. Нужен `crypto.randomUUID()`.

**Сортировка по дате сломается.** `parseInt(b.id) - parseInt(a.id)` работает только потому, что id — это временная метка. С UUID это молча вернёт `NaN` и порядок станет случайным. Нужны настоящие поля `createdAt` и `updatedAt`.

**Модель данных пустовата для коллекции, которой делятся.** Сейчас у растения есть имя, цена, заметки и фото. Для сравнения коллекций и вопроса «у кого ещё есть такое» нужен **вид** — отдельным полем, а не свободным текстом в имени. Плюс дата приобретения и откуда взято: у коллекционеров это часть ценности записи.

**`Total: $` — самое интересное, что есть в проекте.** Учёт стоимости коллекции превращает приложение из «ухода за растениями» в инструмент коллекционера. Ближайший работающий аналог — не Planta, а Discogs. Стоит на это опираться, а не прятать внизу экрана.

### Сборка

`npx tsc --noEmit` проходит чисто.

`npx next build` **падает, и это было до моих правок**: `next-pwa@5.6.0` роняет `build-fallback-worker.js` на `Cannot read properties of undefined (reading 'toString')`. Пакет не поддерживается с 2022 года и конфликтует с Next 14 App Router при настроенном `fallbacks.document`. Варианты: перейти на `@ducanh2912/next-pwa` (живой форк), либо убрать `fallbacks` из `next.config.js` и обрабатывать офлайн вручную в service worker.

Полную продакшен-сборку в песочнице проверить не удалось по другой причине: `next/font/google` тянет шрифты из сети на этапе сборки, а сеть там ограничена, и сборка зависает. Прогоните `npm run build` у себя.
