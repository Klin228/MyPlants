# MyPlants

Веб-приложение: каталог коллекции растений, которым можно будет поделиться по ссылке.

**Это не приложение про уход за растениями.** Никаких поливов, напоминаний и графиков ухода — этим занимаются Planta и Greg, и там нам делать нечего. Наш продукт про **коллекцию**: что у меня есть, сколько это стоит, и как показать это другим. Ближайший работающий аналог — Discogs, а не Planta.

Разбор текущего состояния кода: `REVIEW.md`. Бэклог: `TASKS.md`. Запуск на маке: `SETUP-MAC.md`.

## Команды

```bash
npm run dev                 # разработка, localhost:3000
npm run dev -- -H 0.0.0.0   # доступ с телефона по локальной сети
npx tsc --noEmit            # проверка типов, быстро
npm run build               # продакшен-сборка
```

**После любой правки прогоняй `npx tsc --noEmit`.** Не отчитывайся о выполненной задаче, не увидев чистую проверку типов.

`npm run build` сейчас падает из-за `next-pwa` — см. тикет A2. Пока он не сделан, ориентируйся на `tsc`.

## Стек

Next.js 14 App Router, React 18, TypeScript, `lucide-react` для иконок. Стили инлайновые. Сторонних библиотек почти нет и добавлять их без согласования не нужно.

Хранение — IndexedDB через слой репозиториев:

```
lib/db/            подключение и схема
lib/repositories/  plantsRepository, photosRepository
lib/models/        типы Plant, Photo
```

## Фотографии — читай это перед любой правкой, связанной с изображениями

Здесь была главная проблема проекта, и её легко вернуть обратно.

**Никогда не используй `FileReader.readAsDataURL` для показа фотографий.** Base64 на треть больше двоичных данных, целиком лежит в памяти строкой и заново декодируется при каждой перерисовке. Раньше так и было, и приложение захлёбывалось: свайп дёргался, на iOS вкладку выгружало из памяти.

Правильно: `photosRepository.getByPlantId(keys)` возвращает **object URL**. Это указатель на блоб, а не копия.

**Каждый object URL обязан быть освобождён.** Кто получил — тот и освобождает через `photosRepository.revokeUrls(urls)` в `cleanup` эффекта. Иначе блобы висят в памяти до перезагрузки вкладки. Образцы — `components/FullscreenPhotoViewer.tsx` и `components/PhotoGallery.tsx`, оба освобождают в `cleanup` и оба гасят указатели, созданные уже после отмены эффекта.

**Новые фотографии уменьшаются перед записью в базу** через `resizeToJpeg` из `lib/images.ts` — ту же функцию, которой пользуется публикация. Второй библиотеки сжатия в проекте нет и не нужно: здесь долго значился `compressImages` из `lib/imageCompression.ts`, которого никогда не существовало.

Два размера, оба в `lib/images.ts`: `LOCAL_PHOTO_MAX_SIZE` (1600) для записи на устройство и `PUBLIC_PHOTO_MAX_SIZE` (1200) для публикации. Локальный больше намеренно — полноэкранный просмотр на плотном экране требует больше 1200, и публикация уменьшает из этого блоба, а не пережимает его в тех же размерах.

**Зависимость эффекта по массиву ключей берётся по содержимому, а не по ссылке.** `plant.photos` приходит новым массивом при каждом чтении из IndexedDB, поэтому `useEffect(..., [photos])` срабатывает вхолостую и перечитывает все фото. Используй `photos.join('|')`.

## Жесты

Свайп переписан в `FullscreenPhotoViewer.tsx` и `PhotoGallery.tsx` — оба образцы, пороги у них общие. Правила, которые надо сохранять:

- **Ось жеста определяется один раз за касание** и дальше не меняется. Если палец пошёл вертикально — это скролл страницы, не вмешиваемся. Без этого прокрутка ленты случайно открывает фото на весь экран.
- `touch-action: pan-y` на контейнере — вертикаль отдаём браузеру, горизонталь обрабатываем сами.
- **Не проверяй координату на истинность.** `if (!touchStart)` ломается при касании у левого края экрана, где X равен нулю. Только `=== null`.
- **Тап определяется по фактическому сдвигу и времени**, а не по отсутствию события `touchmove` — на реальном пальце дрожание есть всегда.
- Лента следует за пальцем во время жеста, а не прыгает на отпускании.
- **Не вешай глобальные слушатели клавиатуры в компонентах, которые рендерятся списком.** Двадцать карточек — двадцать слушателей, и стрелки листают всё одновременно. В галерее слушатель висит на контейнере: точки это настоящие кнопки, фокус попадает на них табом, событие всплывает.
- **Режим жеста держи в ref, а не только в состоянии.** `touchstart` и `touchend` — разные события, и рассчитывать, что React успеет перерисоваться между ними, не стоит. Состояние нужно для отрисовки, решения принимаются по ref — так же, как сдвиг ленты в просмотрщике.

## Данные

```ts
Plant {
  id: string
  name: string
  photos: string[]   // ключи в IndexedDB, не блобы
  price: number
  notes?: string
}
```

Модель будет расширяться под шеринг — тикеты B1–B3. Ключевое: `id` сейчас `Date.now().toString()`, это сломается при синхронизации, нужен `crypto.randomUUID()`. Сортировка по дате через `parseInt(id)` держится только на том, что id это временная метка, — нужны настоящие `createdAt` и `updatedAt`.

## Приватность

Коллекция и фотографии — личные данные пользователя. Пока всё лежит только на устройстве, и это правильное состояние по умолчанию.

Когда появится шеринг: **на сервер уходит только то, чем пользователь явно решил поделиться, по явному нажатию.** Никакой фоновой синхронизации без спроса, никакой аналитики по содержимому коллекции. Поделился — значит согласился, и это должно быть отменяемо.

---

## Аналитика

Счётчики событий — свои, `lib/analytics.ts`, без `posthog-js`. У библиотеки по умолчанию включён autocapture: она сама собирает нажатия, переходы и содержимое полей. Обещание выше держалось бы тогда на наборе флагов в конфиге, а не на том, что отправлять больше нечего.

Отправляются ровно одиннадцать событий из размеченного объединения типов, и только числа, логические значения и строки из белого списка. Произвольная строка не пройдёт: заменится на `unknown`. Адрес публичной страницы маскируется до `/c/*` — идентификатор коллекции в аналитику не уходит.

Включается двумя переменными: `NEXT_PUBLIC_POSTHOG_KEY` (публичный ключ проекта, `phc_...`) и `NEXT_PUBLIC_POSTHOG_HOST`. Без них отправка молчит, и приложение работает как раньше.

**Добавляя событие, добавляй его в объединение типов, а не строкой.** И если понадобится новое строковое свойство — сначала в белый список.

## Чего не делать

- Не добавлять уход, поливы и напоминания. Это другой продукт, и он занят.
- Не возвращать base64 для показа изображений.
- Не подключать сторонние UI-библиотеки без согласования.
- Не отправлять ничего на сервер вне явного действия пользователя.
- Не передавать в аналитику ничего из содержимого коллекции: ни названий, ни видов, ни цен, ни заметок, ни идентификаторов публикаций.
- Не считать задачу готовой, не прогнав `npx tsc --noEmit`.
